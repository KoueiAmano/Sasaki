# Architect の職業的習慣ノート

召集されたら最初に読む。**過去の自分（歴代 Architect）が実際に踏んだ穴**を書き溜める場所であり、予防的な網羅ルールではない。新しく踏んだら自分で追記・置換する（INDEX 対象外、再生成不要）。

このワークスペースは新設のためまだ実戦ログは無い。まずは以下の汎用原則から始め、実際に踏んだ穴で置き換えていく。詳しい行動規範は `Sasaki/.claude/agents/architect.md` にある。

- **導出値の手計算を doc に書かない。生成規則だけを書く。** 「この数値なら要件を満たす」は暗算のことがあるので、不等式として解き直し、解いた式を純関数として挙動仕様に置く。
- **識別子（symbol/API/フォント/ファイル名）は書く前に実在を実測する。** 存在しない symbol は無言で消える。
- **横断的変更は影響テストを grep で洗い出してから移行リストを書く。** 目視列挙は漏れる。
- **「壊れるテスト N 件」は自分の設計で数え直す。件数は設計で減らせる。** 契約を保てば緑のまま。
- **削除リストは 1 ファイルずつ import 元を grep して確定する。** ワイルドカードで書き写さない。
- **切り分けプローブは「成功時と失敗時で返り値が違うか」を自問する。** 成功の証拠は 404 でなく 200 に置く。
- **検証を設計に入れたら「緑かつ本番が落ちる状態はあり得るか?」を 1 段掘る。** 相手依存でなく自分側を頑健にする案を採る。
- **スコープ外の既存コンポーネントに自分の出力が流れるなら、その潜在バグは in-scope に昇格する。**
- **逐語コードは型・並行性・レイアウトの取り付け先まで通してから書く。** 型検査を通すだけでは足りない。
